# Tiny File Manager для MajorDoMo

Модуль-оболочка над [Tiny File Manager](https://github.com/prasathmani/tinyfilemanager) - простой, быстрый и маленький файл-менеджер с редактором кода. 

## Состав

```
modules/tinyfm/tinyfm.class.php      — модуль MajorDoMo (меню панели: Приложения → Tiny File Manager)
modules/tinyfm/app                   — маркер MajorDoMo: модуль виден в «Приложениях» (/apps.html)
modules/tinyfm/config.php            — внешний конфиг TFM: SSO через сессию MajorDoMo
modules/tinyfm/assets_install.php    — скачивание дополнительных библиотек из npm (кнопка в настройках)
modules/tinyfm/tinyfilemanager.php   — upstream + правка fm_get_size() (tinyfilemanager.fm_get_size.diff)
modules/tinyfm/translation.json      — upstream (русский перевод)
modules/tinyfm/LICENSE               — GPL-3.0 (Tiny File Manager)
modules/tinyfm/assets/               — основные библиотеки (входят в модуль, ~1 МБ)
modules/tinyfm/assets-extra/         — дополнительные: редактор ace, темы подсветки (скачивание по кнопке)
templates/tinyfm/tinyfm.html
templates/tinyfm/action_admin.html
templates/tinyfm/action_usual.html   — фронтенд (/apps/tinyfm.html)
img/modules/tinyfm.png               — иконка модуля 60×60 (панель, «Модули»; логотип tinyfilemanager.github.io)
```

## Как работает доступ

1. Когда дмин открывает модуль в панели (`/admin.php?md=panel&action=tinyfm`).
   `tinyfm::admin()` повторяет проверку `panel.class.php` и кладёт в сессию MajorDoMo
   (`prj`) пропуск `TINYFM` с настройками (корень, только чтение, часовой пояс).
2. Iframe открывает `/modules/tinyfm/tinyfilemanager.php`. TFM подключает `config.php`,
   который читает сессию `prj`, проверяет `TINYFM` **и** `AUTHORIZED`, закрывает её
   и возвращает TFM его собственную сессию `filemanager`.
3. Выход из панели (снятие `AUTHORIZED`) или истечение сессии MajorDoMo (1 час
   бездействия) → 403. Собственный логин TFM (admin/admin@123) отключён полностью.

### Настройка «Только для администраторов» (включена по умолчанию)

* **Включена:** доступ только из панели управления или пользователю с `IS_ADMIN=1`
  в «Приложениях».
* **Выключена:** любой пользователь MajorDoMo открывает TFM в «Приложениях»
  (`/apps/tinyfm.html`) с теми же правами (корень, запись). Пропуск такого
  пользователя (`MODE=user`) `config.php` перепроверяет **на каждом запросе** по БД
  (пользователь существует, `ADMIN_ONLY` всё ещё 0) — включение галочки отзывает
  доступ сразу. Ошибка БД → 403.
* Внимание: MajorDoMo автоматически входит под пользователем без пароля и под
  пользователем по умолчанию — при выключенной галочке TFM получит любой в сети.

### Настройка «Тема как в MajorDoMo» (включена по умолчанию)

Светлая/тёмная тема TFM повторяет правило самой панели (`common_header.html`):
тёмная, только если `SETTINGS_THEME = dark` **и** cookie `theme` (переключатель на
дашборде) установлена и не `light`. Из «Приложений» — тема фронтенда (`THEME`).
Переключили тему на дашборде — TFM подхватит её при следующей загрузке.
Пока галочка включена, выбор темы в настройках самого TFM не действует.
Вместе с темой меняются редактор кода (ace: `textmate` ↔ `tomorrow_night`) и подсветка
при просмотре (highlight.js: `vs` ↔ `vs2015`).

### Темы подсветки и редактора кода

В настройках модуля два списка; по умолчанию «Автоматически» (пара светлая/тёмная выше,
а при выключенной синхронизации темы — значения TFM по умолчанию). Выбор сохраняется.

* **Тема редактора кода** — те же 37 тем, что в меню редактора TFM (светлые и тёмные).
  Выбор в меню самого редактора действует только до перезагрузки страницы.
* **Тема подсветки при просмотре** — темы, которые есть на диске: встроенные `vs` и
  `vs2015`, а после скачивания дополнительных библиотек — все ~250 тем highlight.js
  (включая `base16/…`). Если выбранной темы нет локально, она грузится с CDN.

### Настройка «Язык как в MajorDoMo» (включена по умолчанию)

Язык TFM = язык MajorDoMo: `SETTINGS_SITE_LANGUAGE` или выбранный через `?lang=`
(`$_SESSION['lang']`, читается на каждом запросе). Коды переводятся: `cs→cz`,
`el→gr`, `zh→zh-CN`; остальные совпадают. Если для языка системы нет перевода
в `translation.json`, остаётся язык из настроек самого TFM.

## Установка

Модуль самодостаточен (~490 КБ): код, шаблоны, иконка и основные библиотеки —
всё работает без интернета.

После установки модуль доступен в меню "Приложения" и по ссылке ```/admin.php?md=panel&action=tinyfm```.

## Библиотеки

Tiny File Manager подключает библиотеки с CDN; `config.php` подменяет их на локальные —
для каждой отдельно и только если её файл есть на диске (иначе остаётся CDN).

**Основные — входят в модуль** (`modules/tinyfm/assets/`, ~1 МБ): с ними без интернета
работает всё — оформление, иконки, таблица, скачивание, удаление, загрузка, обычный
редактор, подсветка при просмотре (темы `vs` / `vs2015`).

| Пакет npm | Версия | Файлы |
|---|---|---|
| `bootstrap` | 5.3.3 | `bootstrap.min.css`, `bootstrap.bundle.min.js` |
| `jquery` | 3.6.1 | `jquery.min.js` |
| `font-awesome` | 4.7.0 | `font-awesome.min.css`, шрифты `woff2` / `woff` |
| `dropzone` | 5.9.3 | `dropzone.min.{css,js}` |
| `datatables.net` | 1.13.1 | `jquery.dataTables.min.js` |
| `@highlightjs/cdn-assets` | 11.9.0 | `highlight.min.js`, `styles/vs.min.css`, `styles/vs2015.min.css` |

**Дополнительные — по кнопке «Скачать» в настройках** (`modules/tinyfm/assets-extra/`,
~10 МБ из npm): без них «Улучшенный редактор» грузится с CDN (без интернета не откроется),
а для подсветки доступны только две темы выше.

| Пакет npm | Версия | Файлы |
|---|---|---|
| `ace-builds` | 1.32.2 | `src-min-noconflict/` целиком (редактор, режимы, темы, воркеры) |
| `@highlightjs/cdn-assets` | 11.9.0 | все `styles/*.min.css` |

* Версии — те, что Tiny File Manager 2.6 подключает с CDN. Скачиваемые пакеты
  проверяются по SHA-512 из npm-реестра (`dist.integrity`); при ошибке прежние файлы
  остаются на месте. Обновление модуля через Маркет `assets-extra/` не трогает.
* Можно задать своё зеркало реестра — в `htdocs/config.php`: `Define('TINYFM_NPM_REGISTRY', 'https://registry.npmmirror.com');`
* Установить вручную: `php modules/tinyfm/assets_install.php <htdocs>/modules/tinyfm <htdocs>/cms/cached`.

## Замечания

* `config.php` должен быть доступен на запись: TFM сохраняет свои настройки (язык, тема)
  в его первые 3 строки. При обновлении модуля эти настройки сбрасываются к
  `ru` / `dark`. При включённой синхронизации они используются только как запасные.
* Лицензии библиотек лежат рядом с файлами. bootstrap и jQuery побайтно совпадают
  с CDN-версиями (SRI-хэши из tinyfilemanager.php).
* «Улучшенный редактор» (ace): в upstream он стоит `position:absolute; top:100px`
  и при узком окне или переносе кнопок ложится поверх панели кнопок. `config.php`
  на странице редактора делает его обычным блоком под кнопками и подгоняет высоту
  под окно (вывод фильтруется, `tinyfilemanager.php` не меняется).
* Обратный прокси: upstream строит абсолютные адреса из `HTTP_HOST`, и за прокси,
  который передаёт внутренний адрес, редиректы TFM уводят на него (404). `config.php`
  задаёт `FM_SELF_URL` / `FM_ROOT_URL` от корня сайта (без хоста) — работает с любым
  `Host`. Сам MajorDoMo за прокси всё равно лучше настроить на передачу исходного
  `Host` (nginx: `proxy_set_header Host $host;`).
* Единый вид интерфейса TFM (`tinyfm_ui_fix()` в `config.php`, правка вывода): кнопки
  действий на страницах просмотра, редактора и под списком — отдельные, одного размера,
  подписи без переноса; пункты шапки в одну строку; панель свойств файла на всю ширину
  (до 720 px) с переносом длинного пути; окно расширенного поиска — поле и крестик на одной
  линии, результаты прокручиваются внутри окна, строка результата кликабельна целиком,
  рамки цветом темы; стрелка расширенного поиска в шапке — меню открывается под ней
  (по правому краю) на любой ширине окна, а поле, лупа и стрелка одной высоты (в upstream
  при свёрнутой шапке меню вставало в строку огромной кнопкой); стрелка шире, после поля
  поиска отступ, в свёрнутой шапке поле выше (38 px) — нажатие на стрелку не попадает на
  «Загрузить», которая в upstream начиналась вплотную под ней; поля страницы — сверху
  под шапкой и снизу по ~16 px (в upstream сверху 25 px, а кнопки под списком лежали на
  нижней границе окна). Цвета — родные TFM. Подписи, вписанные в upstream мимо `lng()` («Delete», «Save»,
  «Full Path»), переводятся; для русского — «Скачать» вместо «Загрузка», «байт», подсказка
  в области загрузки.
* Высота фрейма (`action_admin.html`, `action_usual.html`): до низа окна, а в панели на ПК —
  не короче левого меню (раскрыли категорию — фрейм вытягивается следом), чтобы под ним
  не оставалась пустая полоса до конца страницы. Не ниже прежнего `calc(100vh − 180px)`,
  который остаётся и без JS.
* Единственная правка `tinyfilemanager.php` для увеличения скорости перехода по папкам —  в оригинале `fm_get_size()` узнаёт размер
  каждого файла списка внешним процессом (`stat -c%s`, на Windows — `cmd.exe /c for …`
  и COM), чтобы на 32-битном PHP верно показывать файлы > 2 ГБ. Для 64-битных PHP
  (aarch64, x86_64) правка берёт `filesize()` — он точен для любых размеров; на 32-битном
  всё как в оригинале. 
* Скорость списка файлов: `lng()` в TFM на каждый вызов заново разбирает весь
  `translation.json` (~130 КБ), а в списке она вызывается по несколько раз на строку, а `config.php` один раз собирает компактную
  копию (`cms/cached/tinyfm_i18n/<язык>/translation.json`: все языки в списке, перевод —
  только текущего, ~10 КБ) и переходит в её папку — TFM читает файл по относительному
  пути. Список строится в ~3 раза быстрее. Копия пересобирается при изменении
  исходного файла; если записать её нельзя, всё работает как раньше.
* Просмотр офисных файлов через Google/Microsoft viewer в LAN не работает
  (внешний сервис не видит ваш IP) — это ограничение upstream.
* Загрузка файлов идёт чанками по 2 000 000 байт — укладывается в дефолтный
  `upload_max_filesize = 2M`.
* [Tiny File Manager](https://github.com/prasathmani/tinyfilemanager) 2.6 (upstream commit `41491439a6b2`, 2026-07-20). `translation.json` взят без изменений,
`tinyfilemanager.php` — с одной правкой.
